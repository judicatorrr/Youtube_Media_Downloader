# YouTube Media Downloader v2.0.0-alpha31 — Python / PySide6

Первая кроссплатформенная миграция PowerShell/WinForms-версии.

## Что уже перенесено

- тот же общий интерфейс и порядок блоков;
- RU / EN;
- светлая / тёмная тема;
- анализ YouTube через `yt-dlp`;
- выбор оригинальных аудиопотоков:
  - Opus → `.opus`
  - Opus → `.ogg`
  - AAC → `.m4a`
  - AAC → `.aac`
- `.aac` создаётся через FFmpeg `-c:a copy -f adts`, без перекодирования;
- видео-контейнеры MP4 / MKV / WebM;
- фильтрация совместимых видео/аудиопотоков;
- metadata / thumbnail / chapters;
- ручные главы;
- разделение аудио по главам;
- «Сохранить фрагмент»: полный оригинальный поток → локальный `-c copy` фрагмент;
- скачивание оригинальной обложки;
- remux без перекодирования;
- прогресс и журнал;
- System Proxy / Direct-TUN / INCY / Happ / Manual proxy;
- настройки сохраняются в пользовательской папке конфигурации;
- проверка зависимостей при старте;
- если `yt-dlp` отсутствует, приложение предлагает установить его прямо из GUI;
- если не хватает `FFmpeg / FFprobe / Deno`, приложение даёт кнопку перехода на страницу загрузки;
- проверка внешнего IP и локального интерфейса;
- yt-dlp file-access retries (защита от кратковременного WinError 5).

## Почему PySide6

PySide6 использует Qt и работает на Windows, macOS и Linux. В отличие от WinForms,
интерфейс не привязан к Windows и нормально масштабируется на разных DPI.

## Зависимости

Обязательные:
- Python 3.11+
- PySide6
- yt-dlp
- FFmpeg + FFprobe

Желательно:
- Deno — если он доступен, программа автоматически передаёт его yt-dlp как JS runtime.

`yt-dlp` устанавливается автоматически стартовыми скриптами через `requirements.txt`.

FFmpeg/FFprobe пока ищутся:
1. рядом с программой;
2. в `bin/`;
3. в `bin/windows`, `bin/macos`, `bin/linux`;
4. в системном `PATH`.

## Важно про portable/exe/app

Один исполняемый файл нельзя собрать сразу для всех систем. PyInstaller/Nuitka
собирают приложение под ту ОС, на которой выполняется сборка.

То есть позже делаем три отдельные сборки:

- `YouTube Media Downloader Windows`
- `YouTube Media Downloader macOS`
- `YouTube Media Downloader Linux`

Исходники при этом одни и те же.

## Автоматическое обновление зависимостей

В окне **«Проверка зависимостей»** напротив каждого компонента теперь есть
кнопка **«Обновить»**. Она не просто открывает сайт — приложение само скачивает
нужный файл под текущую ОС и архитектуру.

- **yt-dlp** — официальный standalone-бинарник последнего релиза GitHub.
- **FFmpeg + FFprobe** — обновляются парой. Windows: release essentials от
  gyan.dev; macOS/Linux: release ZIP от Martin Riedl FFmpeg Build Server.
- **Deno** — официальный ZIP последнего релиза Deno GitHub.

Файлы кладутся локально в `bin/windows`, `bin/macos` или `bin/linux`.
Администраторские права и изменение системного PATH не нужны. Локальные файлы
имеют приоритет над системными версиями.

Если отсутствует FFmpeg или FFprobe, нажатие **«Обновить»** напротив любого из
них скачивает сразу оба инструмента. После завершения окно автоматически
повторяет проверку и показывает найденные версии.

### Полный bootstrap при первом запуске
Source-версия теперь рассчитана и на «чистый» компьютер.

Перед запуском GUI стартовый скрипт:
1. проверяет наличие **Python 3.11+**;
2. если Python отсутствует — пытается установить его автоматически;
3. создаёт `.venv`;
4. устанавливает `PySide6` и Python-пакеты из `requirements.txt`;
5. проверяет и при необходимости скачивает:
   - yt-dlp;
   - FFmpeg;
   - FFprobe;
   - Deno;
6. после этого запускает приложение.

Windows использует `bootstrap_windows.ps1`.
macOS — `../macOS/START_MAC.command`.
Linux — `../Linux/start_linux.sh`.

Важно: standalone-сборка PyInstaller уже содержит Python runtime внутри,
поэтому системный Python для готового `.exe/.app` не требуется.

## Изменения alpha19 — оптимизация и повторные загрузки

### Быстрее запуск
Проведена оптимизация критического пути запуска приложения:

- проверка версий `yt-dlp` и FFmpeg больше не запускает внешние процессы
  синхронно до появления окна;
- версии читаются отдельным фоновым worker'ом уже после первого отображения GUI;
- проверка внешнего IP также откладывается до запуска event loop;
- пути к `yt-dlp / FFmpeg / FFprobe / Deno` кешируются;
- наличие Python-модуля `yt_dlp` проверяется через `importlib.find_spec`,
  без тяжёлого импорта пакета;
- после установки/обновления зависимости кеш корректно сбрасывается.

### Быстрый compiled build
`../Windows/BUILD_WINDOWS.bat`, `../macOS/BUILD_MAC.command` и `../Linux/build_linux.sh` теперь собирают
PyInstaller **ONEDIR** — это рекомендуемый вариант для максимальной скорости
холодного запуска.

Если нужен один переносимый файл, сохранены отдельные варианты:

- `../Windows/BUILD_WINDOWS_ONEFILE.bat`
- `../macOS/BUILD_MAC_ONEFILE.command`
- `../Linux/build_linux_onefile.sh`

ONEFILE функционально тот же, но стартует медленнее из-за распаковки
PySide6/Python во временную директорию при каждом запуске.

### Если файл уже существует
Перед повторной загрузкой программа определяет существующий итоговый файл и
предлагает:

- **Перезаписать** — yt-dlp получает `--force-overwrites`;
- **Сохранить копию (_1)** — имя автоматически получает `_1`, `_2`, `_3` и т.д.;
- **Отмена**.

Пример:

`Rammstein - Live [VIDEO_ID].mp4`

→

`Rammstein - Live [VIDEO_ID]_1.mp4`

Для OGG/AAC промежуточные файлы теперь скачиваются в отдельную временную
папку, поэтому существующий M4A/Opus другого формата не вызывает ложную
ошибку повторной загрузки.


## Изменения alpha20 — macOS / Linux SSL

Исправлена кроссплатформенная работа HTTPS-сертификатов.

### Что происходило на macOS
Официальный standalone `yt-dlp_macos` содержит собственный набор корневых
сертификатов `certifi`. Если VPN, прокси или локальная сеть использует
сертификат, доверенный в macOS, но отсутствующий в certifi, yt-dlp выдаёт:

`SSL: CERTIFICATE_VERIFY_FAILED — unable to get local issuer certificate`

В режиме **Auto** программа теперь использует:

- Windows → встроенный certifi;
- macOS → системные сертификаты;
- Linux → системные сертификаты.

Это реализовано штатной опцией yt-dlp:

`--compat-options no-certifi`

### Настройки
В «Подключение к YouTube» добавлен раздел HTTPS-сертификатов:

- Auto — рекомендуемый;
- Системные сертификаты macOS / Linux;
- Встроенный certifi;
- Не проверять сертификаты — только аварийный вариант, потому что отключает
  проверку подлинности HTTPS.

Если проблема SSL всё же возникнет, приложение теперь показывает короткое
понятное сообщение вместо огромного traceback yt-dlp.

### Linux
Дополнительно проверен bootstrap:

- минимальная версия Python исправлена с 3.11 до **3.10** — именно 3.10
  требуется синтаксису приложения и современному yt-dlp;
- Debian/Ubuntu больше не пытается обязательно установить `python3.12`,
  которого может не быть в репозитории;
- bootstrap проверяет наличие системного CA bundle и при необходимости
  устанавливает `ca-certificates`;
- `ca-certificates` добавлен также для dnf/pacman/zypper.

### Source dependencies
`certifi` добавлен явно в `requirements.txt`, чтобы ручной режим
«Встроенный certifi» одинаково работал и в source-сборке.


## Изменения alpha21 — macOS Keychain SSL

alpha20 показала важную особенность macOS: `no-certifi` не гарантирует,
что OpenSSL внутри standalone yt-dlp увидит сертификаты из Apple Keychain.

### Новый Auto на macOS
Программа лениво собирает PEM bundle из:

- публичных корней certifi;
- `/etc/ssl/cert.pem`, если он есть;
- `SystemRootCertificates.keychain`;
- `/Library/Keychains/System.keychain`;
- пользовательского `login.keychain-db`.

После этого bundle передаётся yt-dlp через `SSL_CERT_FILE` вместе с
`--compat-options no-certifi`.

Это должно помочь VPN / HTTPS-фильтрам, чей CA установлен в Keychain,
но не виден встроенному OpenSSL.

### Безопасный аварийный fallback
SSL verification больше не отключается автоматически.

Если даже Keychain не помогает, появляется отдельный диалог:

`Повторить без проверки SSL`

Только после подтверждения пользователя включается
`--no-check-certificates`, причём лишь до закрытия приложения.

В нижней строке в таком режиме появляется:

`TLS verification OFF`

чтобы аварийный режим был явно виден.


## Изменения alpha22 — управление runtime и модулями

Скриншот macOS показал сразу две независимые проблемы:

1. yt-dlp был запущен через Python 3.10 и предупреждал, что 3.10 устаревает;
2. Deno не был доступен, поэтому yt-dlp не мог использовать современный
   JavaScript challenge solver YouTube.

### Что изменено

- Python 3.11+ снова является минимальным runtime для source/build workflow;
- BUILD-скрипты предпочитают Python 3.12 и больше не позволяют случайно
  собрать `.app/.exe` на Python 3.10;
- если старая `.venv` создана на Python 3.10, START/BUILD-скрипты удалят её
  и пересоздадут на новом Python;
- bootstrap теперь **обязательно** устанавливает официальный platform binary
  yt-dlp, даже если в `.venv` уже есть Python-пакет yt-dlp;
- благодаря этому yt-dlp больше не зависит от Python runtime приложения;
- Deno теперь считается обязательным компонентом YouTube, а не optional;
- `requirements.txt` использует `yt-dlp[default]`, чтобы source fallback
  содержал совместимый `yt-dlp-ejs`;
- в «Зависимости / Обновления модулей» добавлен Python runtime;
- добавлена кнопка **«Обновить все модули»**:
  yt-dlp → Deno → FFmpeg/FFprobe;
- Python runtime в уже собранном PyInstaller `.app/.exe` не заменяется
  на месте: он является частью самой сборки. Для него окно показывает статус,
  а новый BUILD-скрипт гарантирует корректный Python при следующей сборке.

Актуальная рекомендация: собирать macOS/Windows/Linux приложение на Python 3.12.


## Изменения alpha23 — SSL updater fix на macOS

На скриншоте alpha22 Python уже обновлён до 3.13.5 — с runtime всё нормально.

Новая ошибка возникала в другом месте: окно зависимостей скачивало Deno/yt-dlp/
FFmpeg через Python `urllib`, а сертификатный fix alpha21 применялся только к
процессам yt-dlp. Поэтому updater снова использовал обычный OpenSSL trust store
и получал:

`urlopen error [SSL: CERTIFICATE_VERIFY_FAILED]`

### Что исправлено

- dependency updater теперь использует тот же certificate mode, что и YouTube;
- в Auto на macOS загрузчик зависимостей использует экспортированный
  **macOS Keychain PEM bundle**;
- этот же SSL context применяется к:
  - скачиванию Deno;
  - скачиванию официального yt-dlp binary;
  - скачиванию FFmpeg/FFprobe;
  - GitHub API-проверке новых версий;
  - проверке новых релизов FFmpeg;
- proxy-настройки и certificate mode теперь передаются в фоновые worker'ы
  окна «Зависимости / Обновления модулей»;
- если SSL всё-таки не проходит, вместо голого `<urlopen error ...>` появляется
  понятное сообщение.

Для загрузки исполняемых зависимостей программа намеренно не отключает
проверку сертификатов автоматически: yt-dlp/Deno/FFmpeg — исполняемый код,
поэтому такой fallback был бы небезопасным.

### Если YouTube требует подтверждение, что вы не бот

1. Обновите yt-dlp через раздел зависимостей.
2. Откройте видео в браузере через тот же VPN/proxy, который использует приложение. Пройдите проверку, если она появится.
3. В настройках сети выберите «Cookies → Из браузера», укажите браузер с этой сессией и нажмите «Продолжить». Повторите анализ.
4. На macOS при необходимости разрешите yt-dlp доступ к данным браузера или связке ключей. Если извлечение не работает, выберите файл Netscape cookies.txt, экспортированный из браузера.
5. Если ошибка сохраняется, попробуйте другой сервер/IP VPN. Cookies не гарантируют снятие блокировки YouTube.

Cookies могут давать доступ к аккаунту, не передавайте их другим. У yt-dlp есть предупреждение о риске блокировки аккаунта при его использовании для скачивания; используйте cookies только по необходимости.
Документация: https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp
